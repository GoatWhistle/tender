# Карта требований ТЗ

> Каждое требование ТЗ — с тем, чем оно реализовано, чем проверено и где проверено. Из 11
> обязательных требований 5 проверены на запущенном стенде, 3 закрыты частично, 2 закрыты только
> кодом и тестами, 1 не закрыт: BPMN-схемы в репозитории нет.

**Читайте, если** вы сверяете решение с ТЗ пункт за пунктом · **Связано:** [для жюри](for-jury.md) ·
[доказательства](evidence.md) · [ограничения](limitations.md)

---

## Как читать статус?

| Статус | Что значит |
|---|---|
| **стенд** | Проверено на запущенном стенде по маршруту или e2e-тесту; шаг или тест указан |
| **код** | Есть код и тесты, на запущенном стенде целиком не проверялось |
| **частично** | Закрыта часть требования; что именно не закрыто — в последней колонке |
| **нет** | Не реализовано; причина в последней колонке |

Ссылки на ТЗ — слайды [методических материалов](Презентация_Задачи_Хакатон_Казань_20261009_1900.md).

## Обязательные требования

| Требование ТЗ | Реализация | Проверка | Статус и границы |
|---|---|---|---|
| Изучить данные организаторов, слайд 2 | [Словарь данных КТРУ](Словарь%20данных%20КТРУ.md), разбор XML в [`adapter/ktru_xml.py`](../backend/app/adapter/ktru_xml.py) | `tests/test_catalog.py`; 1 967 позиций, 10 443 характеристики | **код** |
| По описанию определить подходящие характеристики, слайд 2 | Характеристики позиции и факты из текста, шаг «Характеристики» мастера | Шаг 3 [маршрута](for-jury.md), `e2e/sell.spec.ts` | **стенд** |
| Сопоставить значения и единицы измерения, слайд 2 | Парсер чисел, диапазонов и единиц [`domain/units.py`](../backend/app/domain/units.py); OpenJev для перечислимых значений | `tests/test_facts.py`, `tests/test_enum_sessions.py`, [отчёт](../evals/reports/2026-10-10-enum-mapping.md) | **стенд** |
| Привести значения к унифицированному виду, слайд 2 | Нормализация единиц, значения из допустимых в справочнике, словарь синонимов | `tests/test_diagnostics.py` | **частично**; синонимов 6, свободные значения нормализуются только по единицам |
| Поэтапно сужать категории КТРУ до конечного кода, слайд 2 | Правила исключают позиции; шаг «Позиция КТРУ» показывает сужение и причины | Шаг 2 маршрута, `tests/test_rules.py` | **стенд** |
| При неоднозначности уведомить и предложить шаги, слайд 2 | Статусы `needs_clarification`, `ambiguous_in_catalog`, `conflict`; один следующий вопрос | Шаги 2 и 4 маршрута, `test_indistinct_positions_are_ambiguous_in_catalog` | **стенд** |
| Распознавать ошибки с указанием и обоснованием, слайд 3 | Диагностики: опечатка, нет в справочнике, вне диапазона, синоним; ячейка с ошибкой и кнопка исправления | `tests/test_diagnostics.py`, 12 из 12 синтетических случаев, e2e с фикстурой | **частично**; на стенде без GPU-сервиса орфографии диагностики не появляются, проверены на синтетике |
| Удобный веб-интерфейс, слайд 3 | Мастер из четырёх шагов в дизайн-системе Портала поставщиков, витрина | e2e на десктопе и телефоне, axe | **стенд** |
| Тест на реальных кейсах, включая неполные и некорректные данные, слайд 3 | Наборы `dev_v1`, `ste_holdout_v1`, `errors_ru_v1`, `junk_v1` | [Доказательства](evidence.md) | **частично**; реальных строк СТЕ 60, остальное составлено командой |
| Возможность масштабирования, слайд 3 | Порты на каждую модель и хранилище, сервисы моделей отдельно, API без состояния вне базы | [Архитектура](architecture.md#что-заменяется-без-правки-кода) | **код**; нагрузка не измерялась, база — SQLite |
| Схема реализации в нотации BPMN, слайд 3 | — | — | **нет**; есть схема компонентов и потока в [архитектуре](architecture.md) |

## Ограничения ТЗ

| Ограничение | Как соблюдено | Статус |
|---|---|---|
| Linux и веб-интерфейс, слайд 6 | Бэкенд и сервисы моделей в Docker на Linux, интерфейс в браузере | **стенд** |
| Без платных поисковых API и проприетарных LLM, слайд 6 | Только открытые модели локально: [зависимости](dependencies.md) | **стенд** |
| Открытые модели до 40 ГБ VRAM, слайд 7 | 37 126 МиБ на A100 40 ГБ, [замер](evidence.md#хватает-ли-40-гб-видеопамяти) | **стенд** |
| Без low-code и no-code платформ, слайд 6 | Код на Python и TypeScript | **стенд** |

| Отслеживать подбор кода в реальном времени | Каждое сообщение и ответ пересчитывают сужение сразу | **стенд** |

## Какие допущения приняты вместо ответа организаторов?

| Неясность в ТЗ | Наше допущение | Что изменится, если допущение неверно |
|---|---|---|
| Какие категории КТРУ брать, слайд 11 | Одежда, мебель, инструменты: 1 967 позиций из актуального XML | Нужно загрузить другие XML и пересобрать векторы групп |
| Что приоритетнее: справочник или выгрузки СТЕ, слайд 13 | Справочник КТРУ — источник правил, выгрузки — только примеры формулировок | — |
| Можно ли выдать код при неразличимых позициях | Нет: показываем неоднозначность и общие поля | Нужен выбор позиции поставщиком вместо статуса |
