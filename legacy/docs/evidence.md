# Доказательства

> Каждое утверждение проекта — с тем, как оно известно: измерено, закреплено проверкой, проверено
> вручную или только предполагается. Самое сильное: код выдаётся только после сужения до одной
> позиции по правилам справочника, это закреплено тестами. Самое слабое: на реальных названиях из
> выгрузок СТЕ правильная группа попадает в топ-5 только для 27 описаний из 42.

**Читайте, если** вы хотите знать, какой вес выдерживает число из README · **Связано:**
[ограничения](limitations.md) · [план валидации](validation-plan.md)

---

## Как оценивается каждое утверждение?

| Статус | Что значит |
|---|---|
| **Измерено** | Число выдаёт команда в этом репозитории; команда и размер выборки рядом |
| **Закреплено** | Машинная проверка падает, когда свойство перестаёт выполняться |
| **Проверено вручную** | Выполнено на конкретных названных входах, без общего замера |
| **Наблюдалось** | Видели в живом прогоне, не обобщается |
| **Из источника** | Число или правило третьей стороны со ссылкой |
| **Допущение, не результат** | Рассуждение без замера |
| **Неверно, и это сказано** | Свойство, которого читатель мог бы ожидать, но которого у системы нет |

Когда подходят два статуса, ставится более низкий. «Код есть» — не статус.

## Как часто поиск находит правильную группу?

**Гипотеза:** гибрид TF-IDF, векторов Qwen3-Embedding и словаря синонимов кладёт правильную группу в
первые пять результатов, тогда вопрос о назначении выбирает из короткого списка.

**Чем измерено:** `evals/smoke/bench_search.py` и `evals/e2e/run.py` через `POST /api/v1/search`
продукта, без фильтра категории, топ-10. Отчёты:
[поиск групп](../evals/reports/2026-10-10-group-search-qwen.md),
[сквозной](../evals/reports/2026-10-10-e2e.md), [синонимы СТЕ](../evals/reports/2026-10-10-ste-aliases.md).

**На какой выборке:**

| Набор | R@1 | R@5 | R@10 |
|---|---|---|---|
| `smoke_v0`, 46 описаний | 33 из 46 | 42 из 46 | 43 из 46 |
| `dev_v1`, 57 сценариев с группой | 50 из 57 | 55 из 57 | 56 из 57 |
| Реальные СТЕ, 42 строки с группой | 23 из 42 | 27 из 42 | 34 из 42 |

**Чего эта выборка не показывает:** `smoke_v0` и `dev_v1` составлены командой, и часть синонимов
взята из их провалов: это наборы разработки. Независимы только реальные СТЕ, и там результат
заметно хуже.

## Насколько верен выданный код?

**Гипотеза:** когда система говорит «позиция определена», код совпадает с разметкой не реже 95 %
случаев (цель из раздела 15.3 технического плана).

**Чем измерено:** `cd backend && uv run python ../evals/e2e/run.py --embeddings-url …`,
[отчёт](../evals/reports/2026-10-10-e2e.md).

**На какой выборке:** `dev_v1`, 60 сценариев; код выдан в 24, верен в 21 (88 %). Цель 95 % **не
взята**. Неоднозначность сохранена в 6 из 10 случаев, где справочник не различает позиции.

**Чего эта выборка не показывает:** прогон сделан до подключения проверки назначения группы и без
вопросов к поставщику; набор составлен командой.

## Выбирает ли модель группу без оснований?

**Гипотеза:** если назначение в описании не указано, система спрашивает, а не угадывает.

**Чем измерено:** `backend/.venv/bin/python evals/groups/run.py`,
[отчёт](../evals/reports/2026-10-10-group-validation.md). Порог 0,90 зафиксирован до вызовов модели.

**На какой выборке:** 10 описаний столов, размечены вручную. Ошибочных автовыборов 0 из 10,
уточнений 10 из 10, средняя задержка сообщения 6,4 с при топ-5 и 9,0 с при топ-10.

**Чего эта выборка не показывает:** выборка мала и про одну группу товаров; доля случаев, где
группа выбрана без вопроса, здесь нулевая, поэтому точность автовыбора не измерена.

## Верны ли автоматически принятые значения?

**Гипотеза:** значения, которые OpenJev принимает без подтверждения при оценке не ниже 0,90, верны
вместе с привязкой к характеристике.

**Чем измерено:** `backend/.venv/bin/python evals/enum/run.py --threshold 0.90 --holdout
evals/datasets/enum_holdout_v2.json`, [отчёт](../evals/reports/2026-10-10-enum-mapping.md).
Для извлечения свободных значений — `evals/extraction/run.py` и `score.py`,
[отчёт](../evals/reports/2026-10-10-verified-extraction.md).

**На какой выборке:**

| Что | Верных среди автопринятых | Доля автопринятых |
|---|---|---|
| Перечислимые значения, контрольная выборка v2, 30 сценариев | 20 из 20 | 20 из 23 предложений |
| Перечислимые значения, набор разработки, 57 сценариев | 8 из 8 | 8 из 95 предложений |
| Извлечённые факты, Qwen3.5 и проверка NLI | 8 из 9 | 9 из 30 предложений |

**Чего эта выборка не показывает:** контрольная выборка синтетическая, а не поток реальных
поставщиков; 20 значений не подтверждают цель 99 % статистически. Одна ошибка извлечения прошла
весь конвейер.

## Хватает ли 40 ГБ видеопамяти?

**Гипотеза:** все модели работают одновременно на одной карте в пределах условия ТЗ.

**Чем измерено:** `nvidia-smi` на стенде во время прогона,
[`2026-10-10-enum-vram.txt`](../evals/reports/2026-10-10-enum-vram.txt).

**На какой выборке:** одна A100 40 ГБ: OpenJev 10 016 МиБ, эмбеддинги 3 454 МиБ, экстрактор Qwen3.5-9B
23 636 МиБ, всего 37 126 МиБ из 40 960.

**Чего эта выборка не показывает:** пиковую память под нагрузкой нескольких поставщиков
одновременно; значения `gpu-memory-utilization` vLLM резервируют память заранее.
