# API

> Бэкенд отдаёт три группы методов: справочник КТРУ, поиск групп и сессии анализа. Сессия — это
> история сообщений поставщика с ревизиями: каждое сообщение, ответ или правка факта создаёт новую
> ревизию и возвращает полное состояние анализа. Входа и ролей нет: стенд демонстрационный.
> OpenAPI генерируется из кода и открыт в Swagger на `/api/docs`.

**Читайте, если** вы интегрируете интерфейс или проверяете контракт · **Связано:**
[архитектура](architecture.md) · [сессии](sessions.md) · [поиск групп](search.md)

## Какие методы есть?

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/health/live` | Процесс работает |
| GET | `/health/ready` | Справочник загружен |
| GET | `/health/models` | Модель эмбеддингов и индекс поиска готовы |
| GET | `/api/v1/positions` | Позиции КТРУ |
| GET | `/api/v1/positions/{code}` | Позиция с характеристиками, допустимыми значениями и единицами |
| GET | `/api/v1/groups` | Группы: шаблоны и позиции без родителя |
| GET | `/api/v1/groups/{code}` | Группа с конечными позициями |
| POST | `/api/v1/search` | Группы КТРУ по описанию с вкладом каждого метода поиска |
| POST | `/api/v1/sessions` | Новая сессия, ревизия 0 |
| GET | `/api/v1/sessions/{id}` | Последнее сохранённое состояние |
| POST | `/api/v1/sessions/{id}/messages` | Новое сообщение и анализ; заголовок `Idempotency-Key` |
| POST | `/api/v1/sessions/{id}/answers` | Ответ на вопрос последней ревизии или «не знаю» |
| POST | `/api/v1/sessions/{id}/facts` | Новый факт, указанный поставщиком |
| PATCH | `/api/v1/sessions/{id}/facts/{fact_id}` | Правка, подтверждение, удаление, восстановление, разделение факта |
| POST | `/api/v1/sessions/{id}/recalculate` | Пересчёт подбора после правок |
| POST | `/api/v1/sessions/{id}/enum-resolutions` | Принять, выбрать другое или «не знаю» по предложенному значению |

Контракт сессии, идемпотентность и примеры — в [сессиях](sessions.md); поиск, его параметры и
формат ответа — в [поиске групп](search.md).

## Что возвращает анализ?

Каждый метод сессии возвращает `SessionState`:

| Поле | Что в нём |
|---|---|
| `status` | `draft`, `needs_clarification`, `resolved`, `ambiguous_in_catalog`, `conflict`, `out_of_scope`, `technical_error` |
| `path` | Категория, выбранная группа и число позиций или `null`, если группа не выбрана |
| `candidates`, `candidate_counts` | Позиции группы, исключённые с причиной, и счётчики сужения |
| `alternatives` | До пяти других групп с оценкой и вкладом методов поиска |
| `facts` | Значения с источником в тексте, происхождением и статусом |
| `errors`, `normalizations` | Диагностики: опечатка, значения нет в справочнике, вне диапазона, синоним |
| `next_question` | Один следующий вопрос с вариантами: назначение, различающая, обязательная характеристика, противоречие |
| `enum_proposals` | Предложенные значения, которые ждут подтверждения |
| `missing_required`, `card_complete` | Незаполненные обязательные характеристики и готовность карточки |
| `group_checks` | Результат проверки назначения по каждой группе |

## Как выглядят ошибки?

Ошибка бизнес-правила — HTTP-статус и тело `{"code": "...", "message": "..."}`; сообщение
по-русски. Интерфейс показывает текст по коду, а не поле `message`.

| Код | Статус | Когда |
|---|---|---|
| `session_not_found` | 404 | Сессии нет |
| `idempotency_conflict` | 409 | Тот же ключ пришёл с другим текстом |
| `stale_revision` | 409 | Правка основана на устаревшей ревизии |
| `stale_question` | 409 | Ответ на вопрос не из последней ревизии |
| `option_not_found` | 422 | Варианта ответа нет в вопросе |
| `invalid_fact_edit` | 422 | Правка факта нарушает правила справочника |
| `position_not_found` | 404 | Позиции КТРУ с таким кодом нет |
| `model_not_configured` | 503 | Не задан сервис эмбеддингов |

Сбой модели внутри анализа не превращается в HTTP-ошибку: ревизия сохраняется со статусом
`technical_error` и списком `errors`, чтобы поставщик не потерял текст.
