# Сценарий

Поставщик описывает товар и подтверждает исправления рядом с вводом. Настоящий поиск
возвращает кандидатов, Claude ранжирует их, интерфейс анимирует сокращение выдачи.
После выбора группы сервер уточняет признаки до конкретного кода КТРУ.

Карточка показывает характеристики выбранной позиции. Неизменяемые значения доступны
для просмотра, остальные заполняются из вариантов КТРУ либо обычным текстом через
модель. Дополнительные параметры допускаются только по правилам позиции и проходят
проверку сервера. Пустые обязательные характеристики блокируют завершение.

Пользователь проверяет результат, завершает карточку и скачивает JSON. API и фронтенд
не используют моковые каталоги. Модели требуют настроенного доступа, поиск — готового
индекса. При отсутствии зависимостей интерфейс сообщает об ошибке. Сессии хранятся
в памяти Python-процесса; постоянное хранение и внешняя публикация не реализованы.
