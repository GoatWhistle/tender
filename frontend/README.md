# Фронтенд: Портал поставщиков

React 18 + Vite + TypeScript, Vitest, Playwright + axe, ESLint, Prettier. Весь сайт — в
дизайн-системе Портала поставщиков.

- **Главная** `/` — поиск и категории. **Каталог** `/catalog`, `/catalog/:slug` — фильтр по
  позиции КТРУ и её характеристикам, сортировка, таблица товаров. **Товар** `/product/:id` —
  характеристики позиции, полнота, код КТРУ. Данные витрины отдаёт мок-сервис `mock-api/`.
- **Поставщику** `/sell` — мастер из четырёх шагов на бэкенде (`/api/v1/sessions`).
  Прежний экран — `/sell/classic`.

```bash
cd frontend
npm ci
npm run mock-api                          # мок витрины на http://localhost:8001
STOREFRONT_URL=http://localhost:8001 API_URL=http://localhost:8000 npm run dev
npm run lint && npm run format:check && npm run typecheck && npm test && npm run build
npm run e2e                               # Playwright: десктоп и телефон, axe, свои серверы
npm run format                            # Prettier переписывает файлы
```

`/api/v1/storefront` Vite отправляет в `STOREFRONT_URL`, остальной `/api` — в `API_URL`.
`SITE_URL` (например `https://portal.example.org`) при сборке делает адреса `og:image` и
`og:url` абсолютными — без него превью в соцсетях и мессенджерах не подтянет картинку.
Бэкенд для `/sell` — корневой `README.md`, «Разработка». e2e поднимают мок и Vite на своих
портах и подменяют API сессий фикстурами (`e2e/fixtures/sell.ts`), GPU и бэкенд не нужны.

## Устройство

- `src/app/portal-shell` — шапка портала, прокрутка с проявляющимся ползунком, режим ввода
  (с клавиатуры движение выключается).
- `src/pages` — `home-page`, `catalog-page`, `product-page`, `sell-page`, `not-found-page`.
- `src/features` — `seller-wizard` (модель `model/`, экраны `ui/`), `catalog-filters`,
  `catalog-search`. `src/entities` — `position`, `product`.
- `src/shared` — токены `styles/tokens`, примитивы `ui/`, движение `motion/` (`Collapse`,
  `usePresence`, `useLoadingIndicator`, `withViewTransition`, `motionMs`), тексты
  `i18n/locales`, тема `theme/`, хуки `hooks/`.

Стили — CSS Modules на токенах; токены объявлены на `:root:has([data-portal])` и не задевают
`/sell/classic`. Все появления и исчезновения — через `Collapse` (вход `@starting-style`,
выход до размонтирования), смена шага мастера — View Transitions, загрузка — затемнение через
200 мс и скелетон, спиннер через 400 мс. Уменьшенное движение и ввод с клавиатуры схлопывают
длительности.

Тема — светлая или тёмная, переключатель в шапке; без сохранённого выбора первая тема берётся из
системы, скрипт в `index.html` ставит её до отрисовки. Язык — RU или EN, словари
`src/shared/i18n/locales`.

Иконки сайта в `public/`: `favicon.ico` (16, 32, 48), `favicon.svg`, `apple-touch-icon.png`,
`icon-192/512.png` и маскируемая для Android, `site.webmanifest`, превью для соцсетей
`og-image.png` 1200×630, все собраны из логотипа `src/shared/assets/portal-logo.svg`.

## Мастер поставщика `/sell`

- Шаги в адресе: `?s=<session_id>&step=position|characteristics|card`; недоступный шаг
  сбрасывается на последний доступный. Карточка открывается, когда позиция определена.
- **Описание** — поле, примеры; при неясной группе — вопрос о назначении (`purpose`).
- **Позиция КТРУ** — путь в справочнике, сужение позиций, различающий вопрос, позиции группы.
- **Характеристики** — таблица по попапу «Добавление характеристик в СТЕ»: характеристики
  позиции (`GET /api/v1/positions/{code}`) с фактами, вопросами, предложениями и диагностиками.
  Строки, требующие действия, первыми; ошибка — ячейкой, как в попапе «Сравнение
  характеристик». Пустые необязательные — под раскрывашкой. Факт без характеристики
  привязывается выбором из характеристик позиции.
- **Карточка** — наименование, категория, код КТРУ, ОКПД2 и итоговая таблица.

Логика сессии — общая `src/lib/sellerSession.ts`.

## Экран поставщика `/sell/classic`

Сначала — поле ввода на весь экран и примеры описаний. После первого ответа поле уезжает в левую
колонку, справа — карточка товара; уже́ 1100 px колонки встают друг под друга. Четыре области:

1. **Описание и история** — поле ввода и сообщения сессии (`messages`). Enter — отправить,
   Shift + Enter — перенос. Пустой текст не отправляется, длиннее 4000 символов — замечание
   без запроса.
2. **Характеристики** — `facts`; пока бэкенд их не извлекает, область пуста.
3. **Кандидаты КТРУ** — путь сужения из `path`: категория → группа (код, название) → N позиций;
   счётчики `candidate_counts`, раскрываемый список `candidates`, другие группы `alternatives`.
4. **Следующее действие** — статус анализа текстом, затем подсказка или сбой. Место под
   `next_question`; ответа на вопрос и правки фактов нет, пока нет эндпоинтов.

Сессия в адресе (`?s=<session_id>`): по ссылке экран восстанавливается через `GET`.

### API

Контракт — `docs/sessions.md` и `/api/docs`; типы — `src/api/types.ts` (`SessionState`,
`SellerApi`), клиент — `sellerApi` в `src/api/http.ts`:

- `POST /api/v1/sessions` без тела — при первой отправке;
- `POST /api/v1/sessions/{id}/messages` `{"text"}` с заголовком `Idempotency-Key`, свой ключ на
  каждую попытку;
- `GET /api/v1/sessions/{id}` — снимок по ссылке.

Клиент различает успешный `SessionState`, ошибку API (`ApiError`: статус и `code` из тела
`{code, message}`; у 422 и 5xx прокси кода нет) и сетевой сбой (`NetworkError`).

Логика экрана без React — `src/lib/sellerSession.ts`, тесты рядом:

- **Устаревший ответ.** Запросы нумеруются по порядку отправки; показан ответ с наибольшим
  номером, ответ с меньшей ревизией той же сессии игнорируется. Тот же текст, пока он в пути,
  повторно не уходит.
- **Сбой.** `status: technical_error` (HTTP 200, `errors[]`), сетевой сбой, 404
  `session_not_found`, 409 `idempotency_conflict`, 422 и 5xx показываются карточкой «Сбой» с
  понятным текстом. Введённый текст остаётся в поле: оно очищается только после успешного
  анализа.
- **Без группы.** `path: null` при успешном статусе — «Группа КТРУ не найдена», не сбой.
- Статусы и числа — из ответа; незнакомый или зарезервированный статус — нейтральная подпись.

## Витрина и мок-сервис

Контракт — `src/api/types.ts` (`StorefrontApi`), клиент — `httpApi` в `src/api/http.ts`:
`GET /api/v1/storefront/{categories, positions, positions/{code}, products, products/{id}}`;
фильтры — повторяющийся `f=<код характеристики>:<код значения>`.

Мок-сервис `mock-api/` (Node, без зависимостей): `server.ts` — HTTP и задержка 120–400 мс,
`catalog.ts` — выдача, фасеты, сортировка, `fixtures.json` — данные. В сборку фронта мок не
попадает.

Фото товаров нет, поэтому список товаров — таблица (`ProductTable`): без выбранной позиции —
колонка «Позиция КТРУ», с позицией — колонки её характеристик (сначала обязательные). На узком
экране строки складываются в блоки «название: значение».

Фасеты — только внутри выбранной позиции КТРУ: у каждой позиции свои характеристики. Счётчик
значения считается без фильтра своей характеристики.

Фикстуры собираются из `var/` (`backend/build_var.py`): позиции КТРУ — настоящие, названия
товаров — из выгрузок СТЕ, значения характеристик выбираются из допустимых значений позиции,
цены и поставщики выдуманы.

```bash
uvx python -I frontend/scripts/build_mock.py var frontend/mock-api/fixtures.json
```

## Стиль

Референс — Bevel (refero.design): белый холст, голубое небо-градиент в шапках страниц, карточки
`#ebf0f8` без рамок, кнопки-капсулы, заголовки Inter 600 с трекингом −0.03em (SF Pro заменён на
Inter из `@fontsource`, работает офлайн). Цвет — только в данных: кольцо полноты обязательных
характеристик (`Ring`) и оттенки категорий в иллюстрациях главной (`SpecPlate`).
