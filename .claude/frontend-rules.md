# Правила фронтенда

Эти правила главнее рекомендаций любых скилов. Если скил советует иначе, побеждает этот текст.

Визуальная система — UI-кит «Портал поставщиков» из Figma, выгрузка и описание лежат в `design/figma/` (см. `design/figma/README.md`). Палитра, шрифты, иконки и значения токенов берутся оттуда в `tokens/`. Правила ниже от конкретных значений не зависят.

## Решения команды
- Интерфейс максимально минималистичный, чтобы глаза не разбегались: один главный сценарий на экране, без декоративных блоков, иллюстраций и лишних акцентов. Цвет — только для действия и для ошибки.
- Формирование карточки СТЕ — таблица, по образцу попапов UI-кита:
  - «Добавление характеристик в СТЕ» (1096px): шапка с наименованием, категорией, моделью и производителем, ниже таблица «Характеристика | Значение | Ед. измерения»;
  - «Сравнение характеристик СТЕ и ценового предложения» (1336px): колонки «введено / по КТРУ», расхождения и ошибки подсвечены ячейкой, слева список найденных позиций.
  Файлы: `design/figma/sections/05-09_pop-ups.svg`, элементы в `design/figma/elements/05-09_pop-ups/`.

## Скилы
- Любой UI (экраны, компоненты, раскладка, UX, a11y) делается со скилами `impeccable` и `ui-ux-pro-max`. Это плагины Claude Code.
- Анимации делаются со скилами `emil-design-eng`, `review-animations` (с её `STANDARDS.md`), `improve-animations`, `find-animation-opportunities` и `animation-vocabulary`. Они лежат в `.claude/skills/` этого репо.
  - `review-animations` обязателен перед сдачей любой фичи с движением;
  - `improve-animations` нужен для аудита и плана улучшений;
  - `find-animation-opportunities` ищет места, где анимации не хватает;
  - `animation-vocabulary` подсказывает название эффекта.
- Скилы работают внутри этих правил. Из `ui-ux-pro-max` бери структуру и проверки UX и a11y, но не готовые палитры и шрифты. `frontend/DESIGN.md` и `frontend/PRODUCT.md` для `impeccable` пиши руками как краткое описание токенов и продукта. Значения живут только в `tokens/`.
- Образцы кода из прошлых проектов в `W:\Projects\hacks`:
  - did_hack: `context/frontend-rules.md` (полная сводка) и `frontend/src/ui/shared/motion/` (примитивы движения);
  - rlt-hack-deploy: `frontend/src/shared/i18n/`;
  - assemblyai-hack: `scripts/checks`;
  - GoatWhistle: `frontend/tests/styles`.

## 1. Жёсткие лимиты
- Файл `.ts/.tsx/.css/.html` не длиннее 250 строк. Длинный файл режь по ответственности, а не механически.
- Комментариев в коде нет совсем: ни строчных, ни блочных, ни JSDoc, ни в CSS, HTML или конфигах. Исключения: `// biome-ignore <rule>: <причина>`, `@ts-expect-error <причина>` и shebang. Неочевидное объясняй в `docs/`, а не в коде.
- Генерируемые файлы (например `schema.gen.ts` из OpenAPI) не подчиняются лимитам строк и комментариев.
- В одной папке не больше 20 исходников. Папки `utils`, `helpers`, `common`, `lib`, `misc`, `core` запрещены.
- Циклических импортов нет. Все импорты стоят в начале файла. Экспорт только именованный, default допустим только там, где его требует инструмент.

## 2. Стек
- React 19, Vite, TypeScript, react-router 7. API-клиент — `openapi-fetch`, типы генерируются из OpenAPI бэкенда и руками не пишутся.
- Все запросы к API идут через TanStack Query: кэш, повтор, инвалидация после действий. `fetch` в `useEffect` в фичах запрещён.
- Для текстов — `i18next` и `react-i18next`, для классов — `clsx`, для иконок — `lucide-react` плюс свой набор.
- Линтер — Biome: отступ 2, ширина 100, двойные кавычки, без точек с запятой, LF. Включены `noDefaultExport`, `noExplicitAny`, `noNonNullAssertion`, `useImportType` и `noConsole` (кроме error/warn), cognitive complexity не больше 15.
- TS работает в strict с `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` и `verbatimModuleSyntax`. Алиас `@/`.
- Тесты: Vitest (папка `tests/` повторяет структуру `src/`), e2e на Playwright с axe.
- UI-китов (shadcn, Radix, MUI, Tailwind) и библиотек анимации не подключаем. Свои примитивы пишем на CSS, WAAPI и View Transitions.
- `npm run verify` запускает `rules && typecheck && lint && test && build`. Фича готова, когда он зелёный.

## 3. Устройство (FSD)
```text
src/
  app/        провайдеры, роутер (routes/*-routes.ts по ролям), guards, shell
  pages/      экран = композиция фич и слотов, без своей логики
  features/   пользовательские сценарии
  entities/   данные и их отображение, запросы *.queries.ts
  shared/
    api/      клиент, schema.gen.ts, types.ts, ApiError
    ui/       примитивы по группам: data-display, forms, layout, overlays, primitives, states
    motion/   примитивы движения
    i18n/     locales/{ru,en}/<ns>.json, resources.ts, форматтеры
    hooks/    useMediaQuery, useStoredFlag, useOnline
    styles/   global.css, reset.css, tokens/*, compose/layout/rows.module.css
```
- Импорты идут только вниз: `app → pages → features → entities → shared`. Соседи по слою друг друга не импортируют, фичи связываются через пропсы и слоты на странице.
- Компонент живёт в папке `kebab-case/` с файлами `name.tsx` и `name.module.css`. У фичи и сущности есть `index.ts` с именованными экспортами. Хуки называются `use-xxx.ts`.
- Пропсы описываются интерфейсом `readonly XxxProps`, варианты — картой `Record<Variant, string>`.
- Повторяющийся блок выноси в компонент в `shared/ui` или `entities`, не копируй разметку. Новый экран собирай из тех же примитивов, что и соседние. Самодельный аналог примитива запрещён.
- Логику и права держит бэкенд. Скрытые данные просто не приходят на фронт, фронт сам не решает, что прятать.

## 4. Тексты и языки
- Языков два, RU по умолчанию и EN. Все тексты интерфейса берутся только из словарей `shared/i18n/locales/{ru,en}/<ns>.json` с неймспейсами по фичам и `common`/`errors`.
- Ключ всегда полный: `ns:path`, на английском. `resources.ts` описывается через `satisfies`, а `i18next.d.ts` выводит тип ключей из `en`, поэтому опечатка в ключе ломает typecheck. Тест проверяет, что набор ключей в ru и en одинаковый.
- `LocaleProvider` сначала берёт сохранённый выбор из `localStorage` (в try/catch), затем `navigator.languages`, иначе ru. Он ставит `<html lang>` и заголовок вкладки.
- Переключатель языка — фича `locale-switch`: кнопка с глобусом открывает `Menu`, где у каждого пункта флаг, название на своём языке и галочка у выбранного.
- Кириллица допустима только в `locales/`. Литеральный текст запрещён в JSX, `aria-label`, `title` и `placeholder`. Ожидаемый текст в тестах тоже берётся из словаря.
- Числа, проценты, даты и деньги форматируются через `Intl` по локали (`useFormatters`), в сообщениях — `{{x, number}}`. Строки из чисел не склеиваем.
- Модель данных не хранит фраз. Статусы отображаются через `Record<Status, MessageKey>`.
- Ошибки показываются по ключу `errors:api.<code>`, при отсутствии ключа — `errors:kind.<kind>`. Поле `message` бэкенда в интерфейс не попадает.
- Длинные тире и точки как разделители запрещены: «A · B», «x — y — z» выдают ИИ-генерацию. Несколько атрибутов выводи отдельными элементами с иконкой и `gap`, а пояснение — отдельным предложением, через двоеточие или скобки. Короткое `–` допустимо только в числовом диапазоне.
- EN-версия полностью английская: аббревиатуры, названия и статусы переводятся. Ассеты с текстом существуют в двух версиях, `.ru.svg` и `.en.svg`.
- Данные от бэкенда (тексты LLM, пользовательский контент) не переводятся и выводятся через `<BackendText>` с `lang` своего языка.

## 5. Анимации
Анимировано всё, включая открытие и закрытие всего всплывающего и раскрывающегося. У каждого типа элемента есть заданное поведение.
- Анимируются только `transform`, `opacity`, `clip-path` и `filter: blur` не больше 2px. Запрещены анимации `width`/`height`, `transition: all`, `ease-in` и `scale(0)`. Вход начинается от `scale(0.95)` с `opacity: 0`.
- UI-анимации короче 300ms, выход быстрее входа, без bounce.
- Миллисекунды и кривые пишутся только в `tokens/motion.css`, keyframes — только в `tokens/keyframes.css`. Компонент берёт их через `--motion-*`. В TS нет чисел-миллисекунд, вместо них `motionMs("--dur-base")`.
- Токены движения:
  - кривые: `--ease-out` cubic-bezier(0.23, 1, 0.32, 1), `--ease-in-out` cubic-bezier(0.77, 0, 0.175, 1), `--ease-drawer` cubic-bezier(0.32, 0.72, 0, 1);
  - длительности, ms: `--dur-instant` 80, `--dur-press` 140, `--dur-fast` 160, `--dur-fast-exit` 110, `--dur-base` 200, `--dur-exit` 140, `--dur-panel` 260, `--dur-slow` 320, `--dur-draw` 900;
  - прочее: `--stagger` 40ms, `--press-scale` 0.97, `--press-scale-surface` 0.99.
- Hover работает только внутри `@media (hover: hover) and (pointer: fine)`. Фокус не анимируется, на всё один общий `:focus-visible`. Действия с клавиатуры не анимируются (`useInputModality`).
- Пагинация, прокрутка к элементу, данные из кэша и смена цвета не анимируются.
- FLIP прерываемый: новый переезд начинается от видимого положения.
- Скелет показывается через 200ms и держится не меньше 300ms. Спиннер показывается через 400ms. Если данные уже есть, используется затемнение `stale`.
- Поведение типовых элементов:
  - кнопки: `:active` scale 0.97 (у поверхностей 0.99); в состоянии pending кнопка не сжимается, ширина постоянна, ставится `aria-busy`;
  - смена экрана идёт через `withViewTransition`;
  - первая загрузка: карточки появляются лесенкой с задержкой `calc(var(--i) * var(--stagger))`;
  - смена содержимого идёт через `Swap`;
  - `Disclosure` анимирует clip-path и opacity, повторный клик разворачивает с текущего кадра;
  - `Select`, `Menu`, `Popover`, `Combobox`: fade, scale 0.95→1 и сдвиг 4px от якоря; `transform-origin` у якоря; переходы через `@starting-style`; закрытие быстрее открытия;
  - у `Dialog` подложка fade, панель scale, фокус на заголовок, тело с `overscroll-behavior: contain`;
  - `Checkbox` рисует галочку через `stroke-dashoffset`, `Switch` двигает бегунок через transform, у `Radio` точка — opacity и scale;
  - `Tooltip`: fade и scale 0.95; следующий тултип в пределах задержки показывается без анимации;
  - тосты входят сбоку, а выходят быстрее, чем входят; ошибка висит 10 с, остальное 5 с; hover ставит паузу; тосты живут в `aria-live`;
  - ползунок полосы прокрутки проявляется при прокрутке и наведении и гаснет после паузы.
- Reduced motion делает движение мягче, а не убирает его: `--dur-*` становятся 1ms, `--stagger` — 0, сдвиги и scale нейтрализуются. Элементы с `data-motion="fade"` получают короткий fade 160/110ms.
- Анимировать можно только через примитивы `shared/motion/` (образец — did_hack): `usePresence`, `useLatched`, `<Swap swapKey>`, `useSlidingIndicator`, `withViewTransition`, `useDetailsMotion`, `motionMs`, `readEasing`, `useReducedMotion`, `useLoadingIndicator`, `settleDelay`.
- Тесты движения проверяют:
  - в CSS вне `tokens/` нет литеральных ms, `cubic-bezier` и `!important`;
  - каждый `--motion-*` ведёт на существующий keyframe;
  - каждый `*-exit` короче соответствующего входа;
  - reduced motion сжимает все `--dur-*`;
  - у каждого типа элемента есть поведенческий тест на `data-state`.

## 6. Свои элементы управления
Все элементы управления свои, на каждую роль один компонент:
- `Button` — запрещён `<button>` со своими стилями в фичах;
- `Select` — запрещён нативный `<select>`;
- `Combobox` и `TagInput` поверх `Popover` — запрещены самодельные абсолютные слои;
- `Menu` и `Popover` в общем `LayerHost`;
- `Checkbox`, `RadioGroup`, `Switch` — запрещены голые checkbox и radio;
- `NumberField` — запрещён `type=number` со стрелками;
- `ScrollArea` (`tabIndex=0`, `aria-label`) плюс глобальные полосы на токенах вместо системной полосы;
- `Disclosure` — запрещён голый `<details>`;
- `Dialog` и `CloseButton`; иконка X в других местах запрещена;
- `Segmented`, `Tabs`, `Stepper`;
- `StatusBadge` (иконка плюс текст) — запрещён статус одним цветом;
- `Stat` (`tabular-nums`), `Card` (`title`, `eyebrow`, `actions`);
- `EmptyState`, `ErrorState`, `Skeleton`, `Spinner`, `Banner`, `Toast`;
- `NoValue` вместо ручных `—`, `-`, `n/a`;
- `Icon` — запрещены SVG и эмодзи прямо в фичах.

Иконки обязательны у пунктов навигации, кнопок действий, статусов, префиксов полей и пустых состояний (48px). Над каждым заголовком секции и в прозе их нет. У иконки-кнопки есть `aria-label` и тултип, у декоративной — `aria-hidden`. Цвет иконки совпадает с цветом текста рядом. Одно понятие — одна иконка с одним каноническим именем. Стиль иконок задаётся вместе с визуальной системой.

Глобальные полосы прокрутки:
- `::-webkit-scrollbar*` с ползунком-таблеткой (`background-clip: padding-box`);
- фолбэк `@supports not selector(::-webkit-scrollbar)`: `scrollbar-width: thin` и `scrollbar-color`;
- цвет ползунка анимируется через `@property --scrollbar-thumb-color`.

## 7. Стили
- Огромных CSS нет. Стили локальные, без повторов, общее переиспользуется.
- Глобальное лежит только в `shared/styles/`. `global.css` подключает `reset.css` и `tokens/{palette,semantic,radius,space,typography,elevation,motion,keyframes}.css`, импортируется один раз в `main.tsx`.
- Всё остальное — CSS Modules рядом с компонентом. Модуль импортирует только свой компонент, селекторы начинаются с класса компонента, неиспользуемых классов нет.
- Блок из 3+ одинаковых деклараций в двух местах запрещён, его надо сделать компонентом или токеном. Общие куски подключаются через `composes:` из `compose.module.css`, `layout.module.css` и `rows.module.css`. `composes` ставится первой декларацией и только в селекторе из одного класса.
- Литеральные цвета, длительности, кривые, тени, радиусы и толщины линий живут только в `tokens/`, дальше используются только через `var(--…)`. Компоненты берут семантический слой (`--surface-*`, `--text-*`, `--action-*`, `--border-*`, `--focus-ring`), палитру напрямую — никогда.
- Компонент объявляет свои локальные custom properties, а модификаторы их переопределяют.
- Тем две, светлая и тёмная. Семантический слой задан дважды, в `:root[data-theme="light"]` и `:root[data-theme="dark"]`. Компонент о теме не знает и не пишет `[data-theme]`.
  - по умолчанию берётся системная тема; выбор пользователя хранится в `localStorage`;
  - тема ставится до первой отрисовки, без вспышки;
  - тест проверяет, что каждый токен задан в обеих темах.
- Сайт занимает всю ширину экрана, узкая колонка по центру запрещена (ИИ-паттерн).
  - у страницы и рабочей области нет `max-width`;
  - поля 24px, на ширине от 75rem — 32px;
  - ширину заполняют панели: сайдбар, список с деталью, фильтры с выдачей;
  - сетки строятся на `minmax()` и `fr`;
  - ограничение ширины допустимо только для прозы (≤ 70ch) и одиночного поля (≤ 480px);
  - на сверхшироком экране добавляется панель, а не растут поля.
- Брейкпоинты только `30/48/64/75/90/120rem`, в форме `min-width: Nrem` или `max-width: (N−0.01)rem`. В `matchMedia` те же значения.
- Шкалы радиусов, теней, размеров текста и отступов фиксированы токенами. Градиентов и эмодзи в интерфейсе нет.
- Шрифты подключаются локально из `public/fonts` с `font-display: swap`, preload и лицензией рядом. Внешних ассетов нет.

## 8. Доступность
- Контраст не ниже 4.5:1 в обеих темах.
- Цель нажатия не меньше 44px.
- `:focus-visible` всегда виден.
- Состояние передаётся не только цветом.
- В `Select`, `Menu` и `Combobox` работает клавиатура: стрелки, Home/End, Esc и возврат фокуса.
- e2e гоняются с axe. Геометрию, фокус и выравнивание тесты не видят, поэтому перед сдачей фичи нужен живой прогон в браузере.

## 9. Проверки `scripts/checks/`
- Каждое правило закрепляется скриптом: договорённость без проверки возвращается. Защита засчитывается, только если её нарочно сломали и проверка упала со своим именем.
- `npm run rules` запускает все проверки одним процессом на весь прогон, а не процессом на файл: на Windows иначе медленно и нестабильно.
- Проверки:
  - file-length, no-comments, package-size, import-cycles, layers;
  - cyrillic, jsx-text, dot-separators, dash-separators;
  - css-literals, css-token-refs, css-modules, css-duplicates, css-transitions, scale-tokens, token-layers;
  - touch-targets, contrast (обе темы), motion-tokens, hover-gate, ts-timings, motion-libraries;
  - icon-alias, global-styles, remote-assets, no-page-max-width.
- Если правила вводятся в существующий код, у проверок есть ratchet-базы в `scripts/baselines/`: записанные нарушения только сокращаются, новые запрещены.

## 10. Порядок внедрения
1. Biome, strict TS, `scripts/checks`, генерация `schema.gen.ts`.
2. Токены (пока нейтральные), `global.css`, reset, motion.
3. i18n: словари, провайдер, переключатель языка.
4. Раскладка FSD, примитивы `shared/ui`, CSS Modules.
5. Примитивы движения, поведение всех элементов, проход скилом `review-animations`.
6. Визуальная система, когда она будет задана: заменить значения в `tokens/`, компоненты не трогать.
