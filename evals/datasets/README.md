| `smoke_v0.json` | 48 кейсов выбора группы и 24 enum-вопроса smoke-замера (#5) | группы по названию; использован для подбора синонимов — не unseen |

| `ste_holdout_v1_ids.txt` | `ID СТЕ` holdout — майнинг синонимов (#31) их исключает | — |

`dev_v1.json` и `ste_holdout_v1.csv` прогоняет сквозной замер `evals/e2e/run.py`; проверку
разметки по справочнику делает `evals/e2e/dataset.py` (команды — README, «Сквозной замер»).
Группы и коды везде — коды КТРУ, не названия: названия групп повторяются, есть и дубли с
опечаткой («Шлейфмашина» рядом с «Шлифмашиной») — допустимы все подходящие.

Обобщённая позиция уровня ОКПД2 — группа без потомков и без характеристик, например
`25.73.30.000-00000001` «Инструмент ручной прочий» (87 из 432 групп), — подходящей группой не
считается: заполнять по ней нечего. Товар, для которого есть только такая позиция, — «вне КТРУ».

## `dev_v1.json`

Набор разработки, не независимый тест: после правок продукта по его ошибкам он перестаёт быть
unseen (§15.1). Коды, характеристики и значения — из XML КТРУ; тексты синтетические.

```json
{
  "id": "mebel-01",
  "category": "Мебель",
  "tags": ["complete", "paraphrase"],
  "messages": ["Стол письменный на металлическом каркасе, столешница ЛДСП"],
  "groups": ["31.01.10.000-00000006"],
  "codes": ["31.01.10.000-00000005"],
  "facts": [{"characteristic": "Тип каркаса", "value": "Металлический"},
            {"characteristic": "Высота", "value": 1800, "unit": "003"}],
  "errors": [{"kind": "typo", "source_quote": "настеная", "suggestion": "Настенная"}],
  "checked": false,
  "note": ""
}
```

- `messages` — сообщения поставщика по порядку; последующее может исправлять предыдущее.
  Поиск и цитаты работают с текстом, склеенным переводом строки.
- `groups` — допустимые группы КТРУ (шаблон или позиция без родителя); пусто — товара в
  справочнике нет, тогда `codes` и `facts` тоже пусты, а среди тегов есть `out_of_scope`.
- `codes` — допустимые конечные позиции этих групп: все, которым описание не противоречит.
  Несколько кодов — неоднозначность, которую система должна сохранить, а не угадать.
- `facts` — что должно быть извлечено из текста: точное имя характеристики КТРУ и значение.
  Текст — как в справочнике; число — с кодом единицы ОКЕИ (`003` мм, `796` шт и т. п.),
  сравнивается после пересчёта в базовую единицу. Отрицание («не концевая») значением не
  становится; при исправлении в фактах — последнее значение.
- `errors` — диагностики в формате `evals/errors/score.py` (§16.1): `kind` — `typo`,
  `value_not_in_catalog`, `out_of_range`, `synonym`; `source_quote` — дословно из текста;
  `suggestion` обязателен у `typo` и `synonym`. `out_of_range` и `value_not_in_catalog` —
  только когда значения нет ни у одной позиции группы, а не «не подходит этой позиции».
- `tags`: `complete`, `incomplete`, `same_name` (позиции группы с одним названием различаются
  характеристиками), `paraphrase`, `negation`, `typo`, `synonym`, `units`, `correction`,
  `out_of_scope`, `out_of_range`, `value_not_in_catalog`.
- `checked` — разметку сверил человек; `note` — почему так размечено.

## `ste_holdout_v1.csv`

Случайная выборка `evals/e2e/sample_holdout.py`: по категории — строки Лист1 выгрузки с
непустым наименованием, без дублей по нормализованному наименованию (регистр, пробелы,
`ё/е`), затем `random.Random("20261010:<категория>").sample(..., 20)`. Колонки:

- `ste_id`, `category`, `name`, `characteristics` (первые 300 символов) — из выгрузки;
- `hint_1` … `hint_5` — top-5 групп лексического поиска продукта (TF-IDF без эмбеддингов):
  подсказка разметчику, не ответ;
- `label` — допустимые группы через `;` или `НЕТ`, если подходящей группы в справочнике нет;
- `checked` — `да`, когда разметку сверил человек; `note` — сомнения и обоснование.

## Как проверить разметку

1. `cd backend && uv run python ../evals/e2e/dataset.py` — без проблем и предупреждений.
2. В `dev_v1.json` для каждого кейса: группа и коды подходят тексту (позиции — через
   `GET /api/v1/groups/{код}` и `GET /api/v1/positions/{код}`), факты и ошибки — то, что в
   тексте действительно сказано; затем `checked: true`.
3. В `ste_holdout_v1.csv` для каждой строки: верна ли группа из `label` (подсказки — не
   ответ, правильной группы среди них может не быть), `НЕТ` — только если подходящей группы
   нет во всём справочнике; затем `checked` = `да`. Сомнения — в `note`.

Разметка обоих наборов независимо сверена по справочнику и полным характеристикам выгрузок:
`checked` проставлен у всех строк.

## `enum_holdout_v1.json`

24 синтетических сценария, зафиксированных до первого прогона `enum_decision_v1` и не
используемых для подбора порога. Содержат локальные схемы характеристик, исходные сообщения и
эталонные пары «характеристика — значение». Отрицание, отсутствие сведений и материал другой
части товара не дают положительного факта. Неоднозначный общий «Материал» имеет пустой gold:
конкретная привязка к такому полю не считается правильной даже при правильном названии материала.
Набор проверяет поведение отдельно от поиска групп и не представляет статистически реальный
поток СТЕ. Независимость означает отсутствие использования для настройки, а не независимую
человеческую разметку. Малая выборка сама по себе не подтверждает точность 99%.

## `enum_holdout_v2.json`

30 новых синтетических сценариев для `enum_decision_v2` и заранее заданного порога 0,90.
Заморожены до первого прогона новой политики. Набор v1 после просмотра результатов не считается
независимым для v2. Поля и формат те же; независимость — от настройки, не от человеческой
разметки. Для воспроизведения используй `evals/enum/run.py --threshold 0.90 --holdout evals/datasets/enum_holdout_v2.json`.
