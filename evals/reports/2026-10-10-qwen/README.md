# Qwen: доставка и ёмкость A100

Замеры 10 октября 2026, время московское. Одна NVIDIA A100 SXM4 40 ГиБ,
драйвер 595.84, vLLM 0.22.1, PyTorch 2.11.0+cu130, Transformers 4.57.6,
XGrammar 0.2.5.post1, Python 3.12.14. OpenJev работает в отдельном окружении.

## Методика

`services/qwen/verify_gpu.py --repeats 20`: HTTP на серверном loopback, три
прогрева короткого extraction prompt, затем по 20 запросов с одним и четырьмя
клиентами. P95 — 19-е значение отсортированной выборки. Измеряется полный ответ,
включая HTTP и JSON. Embeddings: пакеты 1/8/32, один прогрев перед каждой серией.
Сохраняются сырые samples, токены, ответы и VRAM. Время SSH и сети клиента не включено.
Короткий повторяемый prompt не является независимым тестом качества; P95 включает
первую группу параллельных запросов. Это smoke, а не SLO или retrieval/verifier eval.

BF16, vision отключён, thinking отключён, температура 0, контекст 8192,
до 16 последовательностей и 4096 batched tokens у экстрактора. Embeddings:
4096 токенов, до 32 последовательностей, 8192 batched tokens. Включены
chunked prefill, prefix caching и штатные compiled CUDA graphs. FlashAttention2
и Triton/FLA выбирает vLLM на A100. `VLLM_USE_FLASHINFER_SAMPLER=0` убирает
попытку ленивой загрузки sampler-artifacts; runtime использует native sampler.

## 4B: измеренный базовый вариант

| Сценарий | P50, мс | P95, мс |
| --- | ---: | ---: |
| Extraction, 1 клиент | 948.56 | 956.63 |
| Extraction, 4 клиента | 1088.48 | 1477.71 |
| Embeddings, 1 текст | 15.00 | 16.34 |
| Embeddings, 8 текстов | 32.10 | 35.81 |
| Embeddings, 32 текста | 60.29 | 72.18 |

Три модели занимают 26340 МиБ из 40960: OpenJev 9454 МиБ, embedding около
3450 МиБ, 4B engine 13412 МиБ. Значения включают выделенные кеши движков.
Без `orjson` embedding batch 32 имел P50 125.71 мс; после установки и
перезапуска — 60.29 мс (примерно 2.1 раза на этой выборке). Остальные условия
и запросы совпадают; это сравнение коротких серий, а не статистическое доказательство.

Исходные данные: `gpu-baseline.json` до serializer-оптимизации и
`gpu-4b-optimized.json` после неё.

## 9B: проверенный запас

9B загружен в BF16 без quantization и CPU-offload, с тем же контекстом 8192.
Веса текстовой части занимают 16.8 ГиБ. GPU-бюджет движка — 0.60: KV cache
4.65 ГиБ, 107240 токенов; расчёт vLLM — 13.09 полных контекстов 8192 одновременно.
`torch.compile` занял 36.20 с, engine init/warmup — 134.45 с после загрузки весов.

Сразу после запуска три модели занимали 35740 МиБ (34.90 ГиБ). После нагрузки —
36564 МиБ (35.71 ГиБ), остаётся 4396 МиБ (4.29 ГиБ). Процессы: OpenJev 9454 МиБ,
embedding 3454 МиБ, 9B engine 23636 МиБ; небольшой остаток — служебная GPU-память.

`probe_capacity.py`: 16 разных запросов по 7425–7426 входных токенов, каждый
возвращает 12 output tokens по закрытой схеме. Одновременно выполнялись embedding
batch 32 и реальный OpenJev NLI. Все 16 strict-ответов, embeddings и NLI прошли,
OOM нет. Вся группа — 10.35 с, P50 — 9.25 с, P95 — 10.33 с. Наблюдаемый пик VRAM
36564 МиБ, sampling каждые 250 мс. Это 16 клиентов: часть запросов ждёт scheduler,
а не 16 одновременно резидентных полных контекстов 8K. Данные — `capacity-9b.json`.

Финальный короткий benchmark извлекает факт «Высота стола 70 см.» и проверяет
значение, единицу, часть товара и флаги. Каждый ответ — 97 токенов:

| Сценарий | P50, мс | P95, мс | Запросов/с |
| --- | ---: | ---: | ---: |
| Extraction 9B, 1 клиент | 1386.57 | 1411.53 | 0.719 |
| Extraction 9B, 4 клиента | 1538.67 | 1585.03 | 2.619 |
| Embeddings, 1 текст | 15.19 | 16.37 | — |
| Embeddings, 8 текстов | 32.29 | 33.36 | — |
| Embeddings, 32 текста | 61.29 | 71.83 | — |

Данные — `gpu-9b-final.json`. У 4B выше использовался исходный prompt и 105 токенов
ответа; это ориентир, а не сравнение моделей при идентичных prompts. С исходным
prompt 9B терял одиночную высоту и отдавал пустой массив за ~120 мс: этот результат
из `gpu-9b-initial-prompt.json` нельзя трактовать как ускорение extraction.
В финальном варианте сама схема дополнительно передаётся в system prompt,
`raw_value` и `raw_unit` явно объяснены; constrained decoding и валидация остаются.
В четырёх smoke-примерах теперь извлечены высота/материал, части товара,
отрицание и отдельное предположение; нерелевантное сообщение даёт пустой список.
Это маленький проверочный набор, не оценка качества на отложенных данных.

Запуск 9B с пустым новым compile-cache прошёл при `HF_HUB_OFFLINE=1`,
`TRANSFORMERS_OFFLINE=1` и HTTP(S)/ALL proxy на неработающий loopback `:9`;
localhost исключён из proxy. Параметры — `9b-startup-probe.json`. Это проверяет
независимость от обычных HTTP-загрузок при запуске, не изоляцию network namespace.
На стенде оставлен работающий 9B; pinned 4B и команда отката сохранены.

9B — подтверждённый рабочий размер рядом с остальными моделями. Абсолютный потолок
для всех семейств Qwen/quantization этим тестом не установлен; большие модели,
более длинные ответы и увеличение контекста требуют отдельной проверки.

## Strict и содержимое фактов

Реальные adversarial prompts проверяют обязательные поля, enum, типы и запрет
дополнительных полей. Запрос без strict и неподдерживаемый keyword получают 422,
оборванная генерация — 502; превышение контекста — 400. API не отдаёт частичные
факты. Проверяются L2-норма и 1024 координаты каждого embedding.

Воспроизводился 400→503: vLLM отправлял validation error, затем закрывал
HTTP-соединение после ASGI exception; следующий запрос попадал на reused socket.
Шлюз теперь не использует keep-alive upstream (`max_keepalive_connections=0`),
не повторяет generation автоматически. Детерминированный TCP regression-тест
воспроизводил ошибку за ~0.1 с до исправления и проходит после; исходный GPU-прогон
с отказом на overlength и следующими нормальными запросами тоже проходит.

Четыре extraction smoke-пары сохранены целиком. 4B правильно извлекает высоту
и пустой результат для нерелевантного сообщения, но на описании частей товара
записывает `legs/top` в `raw_unit`, а в примере с отрицанием и предположением
теряет второй факт о возможном материале. Это структурно валидные ошибки смысла.
Проверка единиц, verifier и продуктовые eval остаются необходимы; никакой факт
этого API не получает автоматический статус accepted.

## Воспроизводимость и ограничения

Ревизии и SHA256 каждого файла закреплены в `services/qwen/` и `profiles/9b/`.
Повторный запуск проверяет содержимое и использует локальные пути,
`HF_HUB_OFFLINE=1` и `TRANSFORMERS_OFFLINE=1`. Компиляционный кеш отделён от весов.
Первичная загрузка выполнялась через hf-mirror.com; SHA256 LFS сверены с метаданными
публичного Hugging Face. Нужен интернет для первоначальной подготовки окружения.

Vast — непривилегированный контейнер, Docker-in-Docker недоступен: GPU inference
проверен под supervisor с тем же `launch.sh`. Docker Compose обоих профилей
прошёл `config --quiet`, digest базового vLLM-образа сверён через registry.
GPU-запуск готовых Docker-образов не проверен на этом хосте.

Локальные проверки после обновления main: 11 strict unit/TCP-тестов, 21 тест OpenJev,
99 backend pytest, 9 eval-тестов; Ruff check/format, pinned mypy 2.4.0
(42 backend-файла), `git diff --check`.
Backend работает на Mac, каталог содержит 1967 позиций. Постоянный LaunchAgent
SSH-туннеля переподключается после принудительного restart; OpenJev NLI через
него возвращает supported для 70 см и contradicted для 90 см при premise 70 см.
Конфигурация runtime и база хранятся вне Git в `var/local-stack/`.
