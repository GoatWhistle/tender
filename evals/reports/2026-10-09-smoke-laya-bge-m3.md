# Smoke-замер: Laya Multilingual и bge-m3 на КТРУ

**Дата:** 2026-10-09. **Набор:** `evals/datasets/smoke_v0.json`. **Скрипты:** `evals/smoke/`.

Первый замер decision-модели и поиска на реальных данных хакатона. Цель — проверить допуск
Laya из раздела 3.1 плана («Первый лёгкий кандидат; допуск после теста КТРУ») до интеграции.
Это набор разработки (раздел 15.1), а не независимый test: формулировки вопросов подбирались
по его ошибкам.

## Итог

1. **Выбор шаблона КТРУ Laya не доверяем.** Без дообучения её лучший результат 34/48 (только
   top-3 гибрида) против 30/48 у гибрида без модели. При этом она уверенно выдаёт абсурдные
   ответы: «Дрель Stanley» → «Стол лабораторный» (p=0.92), «шуруповерт аккумуляторный» →
   «Удлинитель электрический» (p=0.85).
2. **Режим «10 вопросов да/нет по кандидатам» отбрасываем:** 12/48 и 613 мс — худший по
   качеству и скорости.
3. **Laya пригодна для значений перечислимых характеристик** внутри выбранного шаблона:
   18/24 (наугад ≈ 9/24), 74 мс.
4. **Вероятности Laya не откалиброваны.** Верные ответы бывают с p=0.02–0.17, неверные — с
   p=0.85–0.92. Стартовая политика `p ≥ 0.90` из раздела 7.5 на сырых вероятностях
   неприменима, нужна калибровка.
5. **Поиск кандидатов: гибрид TF-IDF + bge-m3 (RRF)** даёт R@5 = 42/46. Каждый метод по
   отдельности — 39/46.
6. **Вариант «нет подходящей позиции» не работает ни у одного метода.** Laya выбирает его зря
   и пропускает настоящие случаи. По косинусу bge-m3 порог не разделяет: настоящие «нет» —
   0.457 и 0.523, верные попадания — от 0.525.
7. **Бытовые синонимы не понимает ни один метод:** «болгарка» не нашли TF-IDF, bge-m3 и Laya.
   Нужен словарь синонимов (раздел 4.1, «словарь проверенных синонимов»).

## Стенд

| Компонент | Версия |
| --- | --- |
| GPU | NVIDIA GeForce GTX 1660 SUPER, 6 ГБ, драйвер 595.58.03 (нет bf16) |
| Laya | пакет `laya` 0.4.1, `convaiinnovations/laya`, подкаталог `multilingual`, revision `7b928d828b7b0e022f929d9bd2e44165aa270148` |
| PyTorch / Transformers | 2.14.1+cu130 / 5.19.0 |
| bge-m3 | `bge-m3-q8_0.gguf`, `llama.cpp:server-cuda` (`sha256:20b3edfe…`), `--pooling cls`, эндпоинт `/v1/embeddings` по LAN |
| TF-IDF | scikit-learn, `char_wb` 3–5, документ = название ×2 + наименование ОКПД2 |

Задержки Laya измерены на GPU с `torch.cuda.synchronize()`, по одному запросу. Задержка
bge-m3 включает HTTP по LAN.

## Набор

- **48 кейсов выбора шаблона.**
  - 33 реальных наименования СТЕ из `Примеры выгрузок/*.xlsx` (Лист1), выбраны случайно и
    размечены вручную;
  - 15 фраз «как пишет продавец» с опечатками;
  - у 2 кейсов правильный ответ «нет в КТРУ»: «Электрод сварочный», «Дверь стекло».

  `gold` — множество допустимых групп. Группа = шаблон (`isTemplate=true`) или позиция без
  родителя; всего 400 групп.
- **24 вопроса по характеристикам.** Перечислимые характеристики шаблонов «Куртка зимняя из
  кожи», «Стол письменный», «Шлифмашина», «Шуруповерт», «Футболка трикотажная», «Кровать для
  взрослых бытового назначения». Варианты ответа — значения из XML.

Ограничения набора:
- одежда в выгрузке перекошена в сторону рюкзаков и сумок;
- кейсов «нет в КТРУ» всего два;
- одинаковые наименования с разными характеристиками и отрицания не покрыты. Раздел 15.1
  требует 60 кейсов с этими сценариями.

## 1. Поиск кандидатов

R@k — сколько раз допустимая группа вошла в top-k (из 46 кейсов, где она есть).

| Метод | R@1 | R@5 | R@10 |
| --- | ---: | ---: | ---: |
| TF-IDF | 27 | 39 | 41 |
| bge-m3, только название | 31 | 37 | 39 |
| bge-m3, название + ОКПД2 | 28 | 37 | 42 |
| bge-m3, максимум из двух | 31 | 39 | 41 |
| **RRF: TF-IDF + bge-m3 (max)** | 30 | **42** | **42** |

- Индекс 2×400 документов bge-m3 строится за ~9 с, запрос — ~11 мс.
- **bge-m3 лучше на фразах продавца:**
  - «халат медицинский одноразовый процедурный» → верно (0.886);
  - «матрас ортопедический» → «Матрац»;
  - «сапоги резиновые рыбацкие» → «Сапоги резиновые формовые».
- **bge-m3 хуже на точных словах:**
  - «кувалда 5 кг» → «Пила ручная», хотя группа называется «Кувалда»;
  - «табуретка деревянная» → «Шкаф для посуды»;
  - «Бейсболка» → «Матрац».

  Эти случаи TF-IDF находит, поэтому нужен гибрид.
- Тонкие различия внутри одной группы эмбеддинг не различает: «спецодежда зимняя куртка» →
  «Куртка зимняя из текстильных материалов»; «перчатки х/б с ПВХ» → «Перчатки полимерные».

План выбирает `Qwen3-Embedding-0.6B`; здесь проверен bge-m3, потому что он уже был развёрнут на
стенде. Qwen3-Embedding на этом наборе не замерялся.

## 2. Laya: выбор шаблона

Вопрос: `choice`, «К какой позиции каталога КТРУ относится этот товар?». Варианты — названия
групп. «НЕТ» — дополнительный вариант «ни одна из перечисленных позиций не подходит».

| Кандидаты | Верно из 48 | p50 |
| --- | ---: | ---: |
| TF-IDF top-1, без Laya | 27 | ~1 мс |
| Гибрид top-1, без Laya | 30 | ~12 мс |
| Laya: TF-IDF top-5 + НЕТ, варианты с описанием ОКПД2 | 25 | 139 мс |
| Laya: TF-IDF top-10 + НЕТ, с описанием ОКПД2 | 26 | 183 мс |
| Laya: TF-IDF top-20 + НЕТ, с описанием ОКПД2 | 22 | 187 мс |
| Laya: TF-IDF top-10 + НЕТ, только названия | 31 | 140 мс |
| Laya: TF-IDF top-10, 10 вопросов «да/нет» батчем | 12 | 613 мс |
| **Laya: гибрид top-3, только названия** | **34** | 86 мс |
| Laya: гибрид top-3 + НЕТ | 33 | 110 мс |
| Laya: гибрид top-5 | 28–30 | 99–117 мс |
| Laya: гибрид top-5 + НЕТ | 28–29 | 83–99 мс |

- Больше вариантов — хуже, даже когда правильный ответ среди них есть. На гибридном top-5
  Laya проигрывает гибриду без модели.
- Описания ОКПД2 в вариантах ухудшают результат (26 против 31): на каждый вариант остаётся
  меньше токенов.
- Формулировка вопроса меняет результат на ±1–2 кейса.
- Режим «да/нет» сделан как `choice` из двух вариантов (обход известной проблемы `noul`).
  Ранжирование шло по вероятности «да».

**Что Laya исправила на гибридном top-5 (5 кейсов):** «табуретка» → «Табурет» (1.00),
«кувалда» → «Кувалда» (1.00), «Картотека ПРАКТИК» → «Шкаф картотечный металлический» (0.93),
«Кресло для посетителей трёхсекционное» → «Секция стульев многоместная».

**Что сломала из верных ответов гибрида (6 кейсов):**

| Текст | Ответ Laya | p |
| --- | --- | ---: |
| Дрель "Stanley". STDR5510 | Стол лабораторный | 0.92 |
| шуруповерт аккумуляторный 18В два аккумулятора | Удлинитель электрический | 0.85 |
| футболка хлопок женская белая р.46 | Футболка трикотажная детская | 0.36 |
| Вешалка TI_напольная Классикс-ЗД сталь | Стойка напольная | 0.34 |
| Сумка для ноутбука Sumdex PON-111BK | Стол компьютерный | 0.23 |
| Стул … хромированный каркас, кожзам | Стул пластиковый | 0.02 |

**«Нет в КТРУ»:** «Электрод сварочный» → «Сварочный аппарат» (0.86), «Дверь стекло» →
«Сейф металлический». На TF-IDF top-10 + НЕТ Laya 8 раз выбрала «НЕТ», хотя верная группа была
среди вариантов.

## 3. Laya: значения характеристик

18/24 верно, p50 74 мс. Шесть ошибок — там, где нужно знание мира:

| Текст | Характеристика | Laya | Верно |
| --- | --- | --- | --- |
| болгарка 125 мм 900 вт | Вид | Дельтовидная виброшлифмашина | Углошлифовальная машина |
| болгарка 125 мм 900 вт | Тип питания | От аккумулятора | От сети |
| куртка … капюшон отстегивается | Тип капюшона | Отсутствует | Съемный |
| футболка хлопок женская | Тип трикотажного полотна | Синтетическое | Натуральное |
| футболка мужская … с принтом | Наличие изображения | Нет | Да |
| кровать металлическая двухъярусная | Кровать многоярусная | Нет | Да |

Остальные 18 включают пол, материал столешницы, тип каркаса, вид шлифмашины по явному слову,
тип питания и патрона шуруповёрта, комплектацию кровати.

## 4. Ресурсы

- **Laya:** пик VRAM 1 537 МиБ. Задержка 74–190 мс на запрос в зависимости от числа вариантов.
  Карточка модели заявляет ~33 мс; там другая GPU, а у 1660S нет bf16.
- **bge-m3 q8 в llama.cpp:** ~0.7 ГБ VRAM.
- Вместе меньше 3 ГБ при лимите 40 ГБ.

## Что следует для плана

- **Раздел 3.1, роль Laya.** Оставить «сопоставление enum-значений». Убрать «семантическое
  ранжирование» как основание выбора кода, пока нет дообучения и калибровки.
- **Раздел 6.** Кандидатов давать гибридом lexical + dense и словарём синонимов. Цель
  `Recall@100 ≥ 0,98` проверять на расширенном наборе: R@10 = 42/46 уже упирается в синонимы.
- **Раздел 7.5.** Пороги строить на калиброванных оценках. Ранжирование шаблонов — по сумме:
  скор поиска + согласие извлечённых значений с характеристиками шаблона (сверка по КТРУ ловит
  ошибки вида «шуруповёрт → удлинитель») + опционально вероятность Laya.
- **«Нет в КТРУ».** Нужен комбинированный признак: скор, отрыв top-1 от top-2, согласие
  характеристик. Одного порога недостаточно.
- **Раздел 15.1.** OpenJev 4B v5 и Qwen3-Embedding-0.6B не замерены. Набор нужно довести до 60
  кейсов с одинаковыми наименованиями, отрицаниями и исправлениями.

## Воспроизведение

```bash
uv run python -m backend.catalog.build          # var/ktru.json, var/vocab.json
uv run python evals/smoke/make_cases.py         # пересобирает smoke_v0.json (TF-IDF top-20)
# bge-m3 за llama.cpp server, затем гибрид (дописывает hyb10 в датасет):
python evals/smoke/bench_emb.py evals/datasets/smoke_v0.json http://<host>:8089/v1/embeddings
# на GPU-хосте, в окружении с `laya` и torch (CUDA); USE_TF=0, веса заранее в кэше HF:
python evals/smoke/bench_laya.py evals/datasets/smoke_v0.json cuda
python evals/smoke/bench_laya_hyb.py evals/datasets/smoke_v0.json
```

`bench_emb.py` нужны `numpy` и `scikit-learn`, `bench_laya*.py` — `laya` и `torch`. Тяжёлые
ML-зависимости в `pyproject.toml` пока не добавлены.

Источники: [карточка Laya](https://huggingface.co/convaiinnovations/laya) (архитектура,
ограничения, заявленные задержки); XML КТРУ и выгрузки СТЕ из `data/yandex_disk/`.
