# Ограничения

> Всё, чего решение не умеет или не доказало, в одном месте. Самое сильное: на реальных названиях из
> выгрузок СТЕ поиск находит правильную группу в топ-5 только для 27 описаний из 42, а точность
> выданного кода 88 % не достигает цели 95 %. Второе: анализ описаний требует трёх моделей на GPU,
> без них работает только справочник и витрина.

**Читайте, если** вы решаете, насколько доверять результату · **Связано:**
[доказательства](evidence.md)

Статусы — из словаря [доказательств](evidence.md#как-оценивается-каждое-утверждение).

## На реальных названиях поиск слабее

**Статус: Измерено.**

На 42 строках из выгрузок СТЕ с группой в справочнике правильная группа первая в 23 случаях, в
топ-5 — в 27, в топ-10 — в 34. На наборах разработки — 55 из 57 в топ-5. Реальные названия
содержат бренды, артикулы и торговые слова, которых нет в наименованиях групп. Словарь синонимов
— 6 проверенных записей.

Держится: группа не выбирается без подтверждения назначения моделью; если ни одна не подтверждена,
поставщик выбирает из найденных.

**Что закрыло бы ограничение:** словарь синонимов из голов названий СТЕ (размечено 313 голов, 105
привязаны к группам, [отчёт](../evals/reports/2026-10-10-ste-heads.md)) и замер на новой выборке.
**Чего это стоит:** ручная проверка сотен синонимов.

## Точность выданного кода ниже цели

**Статус: Измерено.**

На `dev_v1` код выдан в 24 сценариях из 60 и верен в 21 (88 %) при цели 95 %. Замер сделан до
подключения проверки назначения и без ответов поставщика на вопросы.

**Что закрыло бы ограничение:** повторный сквозной прогон с проверкой назначения и ответами по
разметке. **Чего это стоит:** прогон на GPU и разметка ответов для 60 сценариев.

## Анализ требует GPU

**Статус: Неверно, и это сказано.**

Поиск групп, проверка назначения и извлечение значений работают через локальные модели. Без
сервиса эмбеддингов поиск отвечает 503; без OpenJev сессия получает статус технического сбоя.
Проверенный профиль — одна A100 40 ГБ.

Держится: справочник, витрина, API и все тесты бэкенда и фронтенда работают без GPU; e2e подменяют
API сессий фикстурами.

**Что закрыло бы ограничение:** облачный GPU-стенд. **Чего это стоит:** аренда карты на время
показа.

## Витрина работает на моке

**Статус: Неверно, и это сказано.**

API витрины на бэкенде нет, товары отдаёт [`frontend/mock-api`](../frontend/mock-api/). Позиции КТРУ
и их характеристики в моке настоящие, названия товаров взяты из выгрузок СТЕ, значения выбраны из
допустимых для позиции, цены и поставщики выдуманы.

**Что закрыло бы ограничение:** API витрины поверх карточек, собранных мастером поставщика.
**Чего это стоит:** хранилище карточек и их модерация, вне задачи хакатона.

## Качество проверено на малых выборках

**Статус: Измерено.**

Самая большая независимая выборка — 42 строки СТЕ; проверка назначения — 10 описаний одной группы;
перечислимые значения — 30 синтетических сценариев. Этого хватает, чтобы увидеть грубые ошибки, но
не чтобы подтвердить цели 95 % и 99 % статистически.

**Что закрыло бы ограничение:** размеченная выборка из сотен реальных СТЕ по трём категориям.
**Чего это стоит:** несколько дней разметки.

## Данные справочника только на русском

**Статус: Неверно, и это сказано.**

Интерфейс переключается между русским и английским в шапке, тексты лежат в словарях
[`shared/i18n/locales`](../frontend/src/shared/i18n/locales/), паритет ключей проверяет
`parity.test.ts`. Ответы бэкенда, названия позиций КТРУ и характеристик — на русском.

**Что закрыло бы ограничение:** перевод справочника КТРУ и сообщений бэкенда.

## Что не измерено вовсе?

- **Время заполнения карточки поставщиком.** Пользовательских прогонов не было.
- **Нагрузка.** Задержки измерены на одиночных запросах, параллельные сессии не проверялись.
- **Калибровка оценок моделей.** Пороги 0,90 — сырые оценки, а не вероятности правильности.
- **Распознавание ошибок на реальных описаниях.** Диагностики проверены на 24 синтетических
  случаях; орфография — на 40 текстах.
