# Поиск групп КТРУ по описанию

`POST /api/v1/search` получает описание товара и возвращает top-K групп КТРУ. Для каждой группы
в ответе есть итоговый скор и вклад каждого метода. Код — `backend/app/usecase/search.py`,
домен — `backend/app/domain/search.py`. Метод выбран по smoke-замеру #5; числа продукта —
`evals/reports/2026-10-10-search-qwen3-embedding.md`.

## Метод

Три ранжированных списка групп сливаются reciprocal rank fusion (RRF):

| Метод | Реализация (порт) | Документ группы |
| --- | --- | --- |
| `lexical` | TF-IDF, `char_wb` 3–5, `sublinear_tf` (`LexicalIndex`, `adapter/tfidf.py`) | «название название наименование ОКПД2», нормализован |
| `vector` | косинус эмбеддингов, полный перебор по матрице (`VectorIndex`, `adapter/vector_numpy.py`) | два документа: «название» и «название. наименование ОКПД2»; скор группы — максимум по ним |
| `alias` | совпавшие проверенные синонимы | — |

- **Слагаемое метода** — `вес / (60 + ранг)`, ранг считается с 1. Метод без попадания даёт 0.
  Итоговый скор группы — сумма слагаемых, ответ отсортирован по нему.
- **Веса:** `lexical` 1, `vector` 1, `alias` 2. С весом 1 синоним проигрывает группе, которую
  нашли оба других метода (`2/61`), и не выводит на свою группу (см. отчёт).
- **Порядок.** TF-IDF ранжирует группы с ненулевым скором, векторный поиск — все группы. При
  равных скорах раньше идёт меньший код.
- **Эмбеддинги.** Модель — `Qwen/Qwen3-Embedding-0.6B` за OpenAI-совместимым
  `POST /v1/embeddings` (порт `Embeddings`, `adapter/embeddings_http.py`). Запрос кодируется с
  инструкцией Qwen: `Instruct: Given a product description, retrieve the matching product
  group\nQuery: <текст>`. Документ кодируется без инструкции. Векторы нормирует адаптер.
- **Индекс** строится при старте приложения из групп справочника и проверенных синонимов,
  детерминированно. Справочник, загруженный позже, поиск увидит после перезапуска. Пока
  справочник пуст или модель не ответила, индекс не построен, и каждый поиск пробует построить
  его заново. После сбоя модели следующая попытка — не раньше чем через 30 с, до неё поиск сразу
  отвечает той же ошибкой.

## Код КТРУ в тексте

Код распознаётся по шаблону `\d{2}\.\d{2}\.\d{2}\.\d{3}-\d{8}`; код ОКПД2 без номера не
распознаётся.

- Позиция с таким кодом есть в справочнике — её группа идёт первой с `found_by = "code"`.
  Код конечной позиции ведёт к её группе. Дальше — обычный поиск по описанию.
- Кода нет в справочнике (или его позиция вне групп) — сообщение `ktru_code_not_found` и поиск
  по описанию.
- Группа кода из другой категории, чем `category` запроса, — сообщение
  `ktru_code_other_category`.

## Нормализация

Регистр, пробельные символы подряд, `ё → е` — для TF-IDF, синонимов и кода. Эмбеддинг получает
текст со сжатыми пробелами, но с исходным регистром. Поле `text` ответа — описание как пришло.

## Словарь синонимов

`data/aliases.csv`, UTF-8, заголовок `group_code,alias,source,reviewed`:

| Поле | Что |
| --- | --- |
| `group_code` | код группы КТРУ |
| `alias` | бытовое название: слово или фраза |
| `source` | откуда запись: `manual` — ручная проверка, `smoke_v0` — провал smoke-замера, выгрузки СТЕ (#31) |
| `reviewed` | `true` / `false`; в поиске только `true` |

- **Загрузка.** Синхронизация справочника (`main.sync_catalog`) загружает словарь в таблицу
  `aliases` целиком, вместе с непроверенными записями. Синоним группы, которой нет в
  справочнике, попадает в отчёт синхронизации и в лог.
- **Совпадение.** Нормализованный синоним должен быть целым словом или фразой внутри
  нормализованного описания: «болгарка» находится в «Болгарка Makita 125 мм», «стол» в
  «столешница» — нет. Границы слова — любой символ, кроме букв, цифр и `_`: «мини-болгарка»
  совпадает.
- **Ранжирование.** Группы совпавших синонимов ранжируются по длине самого длинного синонима,
  длиннее — выше.

## API

Запрос:

```json
{"text": "болгарка 125 мм 900 вт", "category": "Инструменты", "limit": 10}
```

- `category` — жёсткий фильтр: `Одежда`, `Мебель` или `Инструменты`. Без неё поиск идёт по
  всем трём.
- `limit` — от 1 до 50, по умолчанию 10.

Ответ — `text`, `groups` и `messages`. Каждая группа в `groups` содержит:

- `code`, `name`, `category`;
- `score`;
- `methods`: по `lexical`, `vector` и `alias` — `rank` (или `null`) и `score` (слагаемое RRF);
- `found_by`: `code` или `description`.

`messages` — сообщения о кодах КТРУ: `code` и `text`.

Ошибки, все со статусом 503:

| Код | Когда |
| --- | --- |
| `catalog_empty` | справочник не загружен |
| `model_not_configured` | нет `EMBEDDINGS_URL` |
| `technical_error` | модель недоступна или ответила невалидно |

Остальные эндпоинты работают и без модели.

## Настройки

`backend/.env` (пример — `backend/.env.example`):

| Переменная | Что |
| --- | --- |
| `EMBEDDINGS_URL` | адрес сервиса без пути |
| `EMBEDDINGS_API_KEY` | Bearer-токен, если сервис его требует |
| `EMBEDDINGS_MODEL` | имя модели в сервисе, по умолчанию `Qwen/Qwen3-Embedding-0.6B` |

## Правило замера

Скрипт — `evals/search/smoke_search.py`. Он прогоняет `smoke_v0` через продуктовый сценарий, с
инструкцией Qwen и без неё.

- **Попадание** — в top-k есть группа с названием из `gold`. `smoke_v0` размечен названиями
  групп: их 400 различных. Продукт ищет по кодам — 432 группы, у части названия совпадают.
- Кейсы с ответом «НЕТ» не считаются.
- Метрики — R@1, R@5, R@10 из 46 кейсов.
- Порог — R@5 не ниже гибрида #5, 42/46.
- `smoke_v0` — набор разработки: часть словаря (`source = smoke_v0`) собрана по его провалам.
