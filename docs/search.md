# Поиск групп КТРУ

`POST /api/v1/search` принимает `description`, необязательную `category`
(`Одежда`, `Мебель`, `Инструменты`) и `limit` (1–50, по умолчанию 10).
Категория — жёсткий фильтр до назначения рангов. Ответ сохраняет исходное описание;
для каждой группы возвращает код, название, категорию, итоговый скор, `found_by`
и `methods`: ранг и вклад `lexical`, `vector`, `synonym`. Неизвестные коды — в `messages`.

## Метод

Нормализация поиска: нижний регистр, схлопывание пробелов, `ё → е`.
Лексический документ: «название название наименование ОКПД2».
TF-IDF: `char_wb`, n-граммы 3–5, `sublinear_tf=True`; нулевое сходство не даёт попадания.
Векторные документы каждой группы: «название» и «название. наименование ОКПД2».
Сходство группы — максимум косинуса двух документов, полный перебор матрицы numpy.
Названия конечных позиций и характеристики в поисковые документы не входят.

RRF с `k=60`: вклад метода `1/(60 + rank)`, отсутствующий ранг даёт 0;
итоговый скор — сумма трёх вкладов. Равные скоры упорядочены по коду группы.
Список синонимов ранжируется по длине совпавшей фразы, затем по коду и тексту.

Код КТРУ распознаётся как `\d{2}\.\d{2}\.\d{2}\.\d{3}-\d{8}`.
Код группы или её конечной позиции поднимает группу на первое место с `found_by=code`;
фильтр категории сохраняется. Неизвестный код даёт сообщение и обычный поиск.

## Модель и настройки

Продуктовый адаптер использует OpenAI-совместимый `POST /v1/embeddings`.
Модель: `Qwen/Qwen3-Embedding-0.6B`, ревизия
`97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`, размерность 1024.
Адаптер нормализует каждый вектор по L2; общая обёртка проверяет число векторов,
размерность, конечность координат и единичную длину.

| Переменная | Значение по умолчанию / назначение |
|---|---|
| `EMBEDDINGS_URL` | Базовый URL с `/v1`; без него поиск отвечает 503 |
| `EMBEDDINGS_MODEL` | `qwen-embedding` — имя развёрнутой модели |
| `EMBEDDINGS_REPOSITORY` | `Qwen/Qwen3-Embedding-0.6B` — источник весов для метаданных сборки |
| `EMBEDDINGS_API_KEY` | Необязательный секрет, хранить только локально |
| `EMBEDDINGS_DIMENSION` | `1024` |
| `EMBEDDINGS_REVISION` | Ревизия выше; должна соответствовать развёрнутым весам |
| `EMBEDDINGS_QUERY_INSTRUCTION` | `Given a product description, retrieve the matching product group` |
| `ALIASES_PATH` | `data/aliases.csv` |
| `DATABASE_URL` | `sqlite:///…/var/tender.db` |

Для запросов добавляется `Instruct: <инструкция>\nQuery: <нормализованное описание>`;
документы отправляются без инструкции. Пустая инструкция отключает префикс.
`/health/models` проверяет доступность указанной модели и готовность индекса;
`/health/live` и чтение каталога работают без настроенной модели.
Сервис `/v1/models` сообщает имя модели, но не commit весов: ревизия задаётся
оператором из конфигурации закреплённого сервиса, а не извлекается из ответа API.

## Словарь

`data/aliases.csv`: `group_code,alias,source,reviewed`.
Синхронизация переносит словарь в `aliases`; записи на неизвестные группы
попадают в `SyncReport.invalid_aliases` и предупреждения. В поиске участвуют только
`reviewed=true`. Нормализованный синоним должен совпасть с целым словом или фразой:
«болгарка» находится в «Болгарка Makita 125 мм», «стол» не находится в «столешница».
В начальном наборе 6 проверенных записей с источниками `manual` и `smoke_v0`.

### Синонимы из выгрузок СТЕ

Скрипт `evals/ste/ste_heads.py` готовит ручную разметку: частые «головы» наименований СТЕ,
ответ продуктового поиска на их примеры и пустой столбец пометки. Размеченная таблица даёт
строки словаря с источником `ste:<файл>#<строка>`.

**Голова** — 1–3 начальных слова наименования после нормализации поиска: начальные
прилагательные и первое слово после них («угловая шлифовальная машина», «шкаф металлический» →
«шкаф»). Прилагательное — окончание `-ый`, `-ий`, `-ой`, `-ая`, `-яя`, `-ое`, `-ее`, `-ые`,
`-ие`, кроме `-ение`, `-ание`, `-тие`, `-ствие`, `-ство` («покрытие» — существительное).
Слова кончаются перед словом с цифрой, латиницей, кавычкой или другим знаком, перед предлогом,
перед словом из `Производителя` (целым, с дефисом; формы собственности и «фабрика»,
«мебельная» и т. п. — не бренд) и после слова с запятой или точкой на конце. Не нашлось слова,
кроме прилагательных, в первых трёх — строка без головы, считается отдельно.

Таблица — из корня репозитория, сервис эмбеддингов уже запущен:

```bash
backend/.venv/bin/python evals/ste/ste_heads.py table \
  --embeddings-url http://127.0.0.1:18083/v1
```

- Выгрузки — `--exports` (по умолчанию `data/yandex_disk/Примеры выгрузок`), файлы
  `Инструменты.xlsx`, `Мебель.xlsx`, `Одежда.xlsx`, Лист1; категория — имя файла.
- Строки holdout #14 исключаются до подсчёта голов: `--holdout`, по умолчанию
  `evals/datasets/ste_holdout_ids.txt`, по одному `ID СТЕ` в строке, `#` — комментарий. Файла
  нет — исключать нечего, это пишется в отчёт.
- Отбор голов в каждой категории — по убыванию частоты, пока не покрыта доля `--coverage`
  (0.9) строк категории, не больше `--max-heads` (300), не реже `--min-count` (2) строк.
- На голову — 3 примера, выбор детерминирован (`--seed`, 38). Каждый пример идёт в
  `POST /api/v1/search` над копией `--database` (`artifacts/ktru-search.sqlite3`), limit 5, без
  категории; векторизация документов запрещена, как в замере ниже.
- Таблица — `--output`, по умолчанию `evals/datasets/ste_heads_v1.csv`: `head`, `category`,
  `n_ste`, `example_rows` (`файл#строка`), `examples`, `top5` (объединённый top-5 примеров: код,
  название, сколько примеров дали группу top-1 и top-5), `label`, `note`. Сортировка — по
  `n_ste` убыв. Повторный запуск сохраняет заполненные `label`/`note` по `(category, head)`;
  размеченная голова, выпавшая из отбора, остаётся в таблице.
- Отчёт — `evals/reports/<дата>-ste-heads.md` и `.json` (`--reports`, `--date`): головы,
  покрытие строк, головы с разным top-1 у примеров, ревизия модели, SHA256 базы. Те же входы дают
  ту же таблицу, кроме `top5`: ответы GPU-сервиса побитово не обещаются.

Пометка `label`: `group:<код КТРУ>` — синоним группы, `none` — товар вне КТРУ, `generic` —
слишком общая голова («набор»), `skip` — не решено. Строки словаря:

```bash
backend/.venv/bin/python evals/ste/ste_heads.py aliases
```

- `group:<код>` даёт строку `<код>,<голова>,ste:<файл>#<строка первого примера>,true`.
- Код не группа справочника (`--database`) или голова уже в словаре — пропуск с причиной.
  Одна голова на разные группы и неизвестная пометка — ошибка с перечнем, словарь не меняется.
- Строки дописываются в конец `--aliases` (`data/aliases.csv`) без перестановки; результат
  проходит загрузку словаря продукта, иначе файл не меняется.
- Печатает добавленные, пропущенные, число пометок каждого вида и список `none` — кандидатов
  в кейсы «вне КТРУ» для #14.

Новые синонимы попадут в поиск после пересборки базы (см. «Воспроизводимая сборка»).

## Готовая база

В Git хранится только подготовленный артефакт
[`artifacts/ktru-search.sqlite3`](../artifacts/ktru-search.sqlite3).
Он содержит все три категории: 1 967 позиций, 432 группы по коду,
10 443 характеристики, 51 181 допустимое значение, 6 aliases и 864 вектора.
Группы включают шаблоны и позиции без родителя; остальные позиции сохраняются
в том же каталоге с родительскими связями. Позиция без потомков сама может быть группой.

`group_search_vectors`: код группы, порядковый номер документа (0/1), его текст
и вектор в little-endian float32 BLOB. `search_vector_metadata`: имя модели,
ревизия, размерность, рецепт `group-name-and-okpd2-v1`, нормализация `L2`,
SHA256 трёх исходных XML и aliases, репозиторий модели, кодировка векторов
и версия нормализации текста. Схема управляется Alembic.
Адрес сервиса, ключи, локальные пути и runtime WAL в артефакт не записываются.

При запуске документы и векторы читаются из SQLite. Проверяются модель/ревизия,
размерность, рецепт, нормализация, полнота и точное соответствие текстов
текущим группам. Несовместимый или повреждённый снимок даёт 503 поиска с
указанием пересобрать базу; документные запросы к сервису не выполняются.
Лексический индекс строится локально при старте. Новые запросы всегда векторизует
реальный сервис. База без сохранённого снимка строит документные векторы через сервис
при старте процесса. Синхронизация справочника удаляет снимок, чтобы старые векторы
не использовались с новым каталогом. После синхронизации процесс нужно перезапустить.

Запуск из готовой базы, из корня репозитория (XML для запуска не нужны):

```bash
mkdir -p var
cp artifacts/ktru-search.sqlite3 var/tender.db
cd backend
uv sync
EMBEDDINGS_URL=http://127.0.0.1:18083/v1 \
  uv run uvicorn --factory main:create_app --host 127.0.0.1 --port 8000
```

Используйте runtime-копию в `var/`. Перед этим запуском не вызывайте `sync_catalog`:
это команда замены каталога, которая удаляет сохранённый снимок.

## Воспроизводимая сборка

Нужны исходные XML организаторов и уже запущенный сервис той же ревизии;
веса команда не скачивает. Из `backend/`:

```bash
uv run python build_search_db.py \
  --ktru-dir /path/to/data/yandex_disk/КТРУ/xml \
  --embeddings-url http://127.0.0.1:18083/v1 \
  --output ../artifacts/ktru-search.sqlite3
```

Путь aliases по умолчанию — `../data/aliases.csv`; можно задать `--aliases`.
Остальные параметры модели и необязательный ключ — через переменные выше или `.env`.
Команда создаёт временную базу, применяет миграции, загружает XML и aliases,
получает реальные векторы, проверяет целостность и внешние ключи, выполняет `VACUUM`
в режиме `journal_mode=DELETE` и атомарно заменяет результат. Ошибка сервиса
сохраняет прежний артефакт. Порядок документов детерминирован; побитовая идентичность
ответов GPU между версиями runtime не обещается, версия весов и исходные хеши сохраняются.

## Замер

Из корня репозитория после установки зависимостей backend:

```bash
backend/.venv/bin/python evals/smoke/bench_search.py \
  --embeddings-url http://127.0.0.1:18083/v1 \
  --database artifacts/ktru-search.sqlite3 --reuse-database \
  --output evals/reports/2026-10-10-group-search-qwen.json
```

Прогон с инструкцией и без неё вызывает продуктовый `POST /api/v1/search`:
limit=10, без фильтра категории. Оба запуска запрещают векторизацию документов;
каждый кейс векторизуется реальным сервисом. Попадание — точное название из `gold`
в top-k, случаи `gold=[НЕТ]` исключены из знаменателя. 46 положительных случаев;
порог для режима по умолчанию — R@5 ≥ 42/46. Датасет содержит 400 групп по названию,
продукт — 432 группы по коду. Готовые `top20`/`hyb10` датасета не используются.

Часть aliases взята из провалов `smoke_v0`, поэтому это development-замер,
не независимый holdout. Подробные результаты и SHA256 базы — в JSON,
краткий отчёт — [2026-10-10-group-search-qwen.md](../evals/reports/2026-10-10-group-search-qwen.md).
