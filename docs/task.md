# Автозаполнение ключевых характеристик в СТЕ

Задание организаторов хакатона «Tender Hack»: текст слайдов с постановкой задачи и исходными данными.

## Слайд 1. Тема хакатона

Автозаполнение ключевых характеристик в СТЕ.

## Слайд 2. Ключевые задачи хакатона

- Изучить предоставленные организаторами данные.
- Реализовать механизм автоматического подбора унифицированных характеристик из предоставленного датасета и справочника КТРУ, который на основе введённого пользователем описания товара:
  - определяет подходящие характеристики для конкретного товара;
  - сопоставляет значения и единицы измерения;
  - приводит их к унифицированному виду;
  - поэтапно сужает множество категорий КТРУ при вводе конкретных характеристик до конкретного итогового конечного кода.

При этом если по введённым характеристикам невозможно однозначно определить КТРУ, система должна уведомить пользователя о необходимости дополнить или скорректировать данные и предложить конкретные шаги.

## Слайд 3. Ключевые задачи хакатона (продолжение)

- Реализовать механизм распознавания и исправления ошибок в характеристиках (опечатки, явные несоответствия, несуществующие значения) с автоматическим указанием на них и обоснованием.
- Обеспечить удобный и интуитивно понятный пользовательский веб-интерфейс.
- Протестировать систему на реальных кейсах, включая сценарии с неполными или некорректными данными.
- Предусмотреть возможность масштабирования системы.
- Продемонстрировать работоспособность проекта.
- Презентовать проект. Разработать схему реализации в нотации BPMN.

## Слайд 4. Возможности пользователя

1. Вводить текстовое описание товара на естественном языке (в том числе с опечатками и неполными данными) и получать унифицированные характеристики, сопоставленные значения и единицы измерения, а в конце и соответствующий код КТРУ.
2. Видеть, как система поэтапно сужает множество кодов КТРУ при вводе новых характеристик, и получать уведомление, если по введённым характеристикам невозможно однозначно определить КТРУ, с предложением дополнить или скорректировать текст и конкретными шагами по исправлению.

## Слайд 5. Возможности пользователя (продолжение)

3. Получать автоматическое уведомление об обнаруженных ошибках в характеристиках (опечатки, явные несоответствия, несуществующие значения) с указанием на них и обоснованием, почему характеристики некорректны и какие необходимо добавить.
4. Видеть в интерфейсе, какие характеристики были унифицированы, какие значения и единицы измерения были сопоставлены, а также отслеживать процесс подбора кода КТРУ в режиме реального времени.

## Слайд 6. Ограничения

1. Решение должно работать на операционной системе семейства Linux и предоставлять веб-интерфейс.
2. Запрещено использовать:
   - поисковые API с платной тарификацией: Yandex Search API, Google Custom Search JSON API;
   - внешние API **проприетарных** больших языковых моделей (LLM): OpenAI GPT, Google Gemini, Anthropic Claude и другие подобные сервисы.
3. Запрещено использовать low-code и no-code платформы.

## Слайд 7. Ограничения (продолжение)

4. Разрешено использовать только **открытые** ML-модели и нейросети при условии, что совокупный объем VRAM, необходимый для инференса, не превышает **40 Гб**. При этом выбор должен быть рациональным и соразмерным задачам и ресурсам. Предпочтение будет отдаваться легковесным решениям с высокой скоростью инференса. Необоснованное применение «тяжёлых» моделей будет считаться нерациональным и может снизить итоговую оценку.
5. Допускается использование роутеров для LLM (в том числе timeweb, selectel), предпочтение отдаётся отечественным решениям.

## Слайд 10. Исходные данные. Справочник КТРУ

**КТРУ** - Каталог товаров, работ и услуг в ЕИС, который содержит стандартизированные позиции для описания объектов закупки.

Для каждой позиции КТРУ могут быть заданы:

- код и наименование позиции;
- связь с ОКПД2;
- **характеристики товара, работы или услуги**;
- **допустимые значения и диапазоны значений характеристик**;
- **единицы измерения**;
- статус и период действия позиции;
- связи с укрупнёнными и родительскими позициями. Приложение 1.

**Назначение КТРУ:** привести описание закупаемых товаров, работ и услуг к единому стандарту и уменьшить различия в формулировках у разных заказчиков.
