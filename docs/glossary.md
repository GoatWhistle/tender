# Глоссарий

> Термины предметной области в том виде, в каком они звучат в интерфейсе, документации и коде.
> Одно понятие — одно слово: «позиция КТРУ» никогда не называется «кодом» или «шаблоном», если речь
> не о них.

**Читайте, если** вы встретили незнакомый термин в интерфейсе или в доках · **Связано:**
[словарь данных КТРУ](Словарь%20данных%20КТРУ.md) · [архитектура](architecture.md)

---

## Какие термины относятся к справочнику?

| Термин | Что значит | В коде |
|---|---|---|
| КТРУ | Каталог товаров, работ и услуг в ЕИС: стандартные позиции с характеристиками и допустимыми значениями | `catalog` |
| Позиция КТРУ | Запись справочника с кодом вида `31.01.11.121-00000003`, наименованием, характеристиками и единицами | `Position` |
| Группа | Шаблон или позиция без родителя; объединяет конечные позиции одного товара | `Group` |
| Конечная позиция | Позиция, к которой привязывается карточка; её код и есть итоговый код КТРУ | `leaves` |
| Характеристика | Свойство позиции: название, обязательность, допустимые значения или диапазон, единица | `Characteristic` |
| Обязательная характеристика | Без неё карточка не считается заполненной | `required` |
| Допустимое значение | Значение из справочника или диапазон с границами | `values`, `rangeSet` |
| ОКПД2 | Классификатор продукции; код и наименование хранятся при позиции | `okpd2` |
| ОКЕИ | Классификатор единиц измерения | `unit` |

## Какие термины относятся к работе поставщика?

| Термин | Что значит | В коде |
|---|---|---|
| СТЕ | Стандартная товарная единица: карточка товара на Портале поставщиков | — |
| Карточка | Наименование, код КТРУ и значения характеристик товара | `card_complete` |
| Описание | Текст поставщика своими словами; может содержать опечатки и неполные данные | `messages` |
| Сессия | История описаний, ответов и правок с ревизиями; каждое действие создаёт новую ревизию | `Session`, `revision` |
| Факт | Значение характеристики из описания, ответа или правки, с цитатой-источником и статусом | `Fact` |
| Неоднозначный факт | Значение, которое нельзя уверенно отнести к одной характеристике | `ambiguous` |
| Предложение | Значение, найденное моделью, которое ждёт подтверждения поставщика | `enum_proposals`, `proposed` |
| Диагностика | Найденная ошибка: опечатка, значения нет в справочнике, значение вне диапазона, синоним | `Diagnostic` |
| Сужение | Исключение позиций группы, противоречащих фактам, с причиной для каждой | `candidates`, `reason` |
| Вопрос | Один следующий вопрос: назначение, различающая или обязательная характеристика, противоречие | `next_question` |

## Какие статусы бывают у анализа?

| Статус | В интерфейсе | Когда |
|---|---|---|
| `draft` | — | Описания ещё нет |
| `needs_clarification` | Нужен ответ | Группа не выбрана или позиций осталось несколько |
| `resolved` | Позиция определена | После правил осталась ровно одна позиция |
| `ambiguous_in_catalog` | Позиции не различаются по справочнику | Оставшиеся позиции не различаются ни одной характеристикой справочника |
| `conflict` | Ни одна позиция не подходит | Факты исключили все позиции группы |
| `out_of_scope` | Описание не похоже на товар | Текст вне справочника или бессмысленный |
| `technical_error` | Сбой | Модель недоступна; текст сохранён, анализ можно повторить |

## Какие термины относятся к моделям?

| Термин | Что значит |
|---|---|
| Проверка назначения | OpenJev оценивает, соответствует ли описание группе: соответствует, противоречит, нет сведений |
| NLI-проверка | OpenJev проверяет, следует ли утверждение из текста поставщика |
| Автопринятие | Значение принимается без подтверждения, если оценка модели не ниже 0,90 на закреплённой ревизии |
| RRF | Слияние рангов трёх методов поиска: вклад метода равен `1 / (60 + ранг)` |
| R@K | Доля описаний, для которых правильная группа есть среди первых K найденных |
